## Замер

### Сверка с документацией (шаг 1)

- `claude --version`: 2.1.300. `npm view @anthropic-ai/claude-agent-sdk version`: 0.3.302. Node 24.21.0.
- Все флаги из Global Constraints есть в `claude --help`: `-p`, `--model`, `--system-prompt`, `--tools ""`, `--safe-mode`, `--setting-sources`, `--strict-mcp-config`, `--no-session-persistence`, `--output-format json|stream-json`, `--input-format stream-json`, `--json-schema`. Есть и `--effort low|medium|high|xhigh|max`, в плане его не было.
- `--bare` по `--help` читает только `ANTHROPIC_API_KEY` или `apiKeyHelper`, OAuth и связку ключей не читает. Подтверждает план.
- Опции SDK сверены по `sdk.d.ts` установленного пакета 0.3.302, а не по страницам документации: `query({ prompt: string | AsyncIterable<SDKUserMessage>, options })`, `model`, `systemPrompt` (строка), `tools`, `settingSources`, `persistSession`, `outputFormat: { type: 'json_schema', schema }`, `cwd`, `env`, `effort`, `thinking: { type: 'disabled' }`, `Query.close()`. Есть ещё альфа-API `prewarm()` и `startup()` (запасной заранее запущенный процесс), в плане не используется.
- Расхождение с планом: у Haiku 5.5 по умолчанию включены адаптивные размышления (около 700-800 токенов на запрос по контексту замера). Это главная часть задержки, см. таблицу.

Наблюдения:

- Запуск процесса стоит около 1 секунды: вызов с пустяковым запросом занимает 1.2-1.4 с, в отвязанном цикле 2.0-3.1 с.
- Основное время - размышления Haiku 5.5 над большим контекстом. Их не выключают ни `--effort low`, ни `MAX_THINKING_TOKENS=0`, ни `--settings '{"alwaysThinkingEnabled":false}'`, ни `thinking: { type: 'disabled' }` в SDK (первый вызов SDK - 813 токенов размышлений).
- В постоянной сессии следующие запросы в 2.5 раза быстрее первого: короткий ввод, кэш подсказки, меньше размышлений. SDK по скорости не лучше CLI, но тянет 105 пакетов и свой Claude Code 2.1.302.
- Нарушения формата - почти всегда третье предложение в `say`. С `--effort low` их больше (5/10).
- Модель везде `claude-haiku-5-5` по алиасу `haiku`. Вход по подписке работает без `ANTHROPIC_API_KEY` и без переменных сессии Claude Code (`apiKeySource: none` в SDK).

### Изоляция (шаг 4)

- `--safe-mode` один: в `system/init` пустые `tools` и `mcp_servers`, событий хуков нет, но в списке `plugins` есть плагины ученика (superpowers и другие).
- `--safe-mode --setting-sources "" --strict-mcp-config`: в `plugins` остаются только встроенные `cc-plugin-agents-md`, `cc-plugin-telemetry`, `cc-plugin-plugin-authoring`, их не убрать. Событий хуков нет. Рабочая папка - `os.tmpdir()/chess-coach-lesson`, `AGENTS.md` там нет.
- Окружение: в Bash этой сессии 31 переменная `CLAUDE*`/`ANTHROPIC*` (в том числе `ANTHROPIC_BASE_URL`, `CLAUDE_CODE_SESSION_ID` и `CLAUDECODE`; значения не смотрел). Убирать все переменные с префиксами `CLAUDE` и `ANTHROPIC`: без них вход по подписке работает, и помощник не зависит от того, откуда запущен.

### Фоновый процесс (шаг 7)

- Отвязанный процесс из инструмента Bash этой сессии (`spawn(..., { detached: true }).unref()`) живёт после конца вызова Bash и после конца хода Claude: 10 вызовов модели за 5 минут, все успешны, родитель - `launchd` (ppid 1). Запускать помощника можно прямо из сессии основного тренера, терминал ученика не нужен.

Скрипт слушал доску по WebSocket и писал в заметку панели вердикт движка, затем ответ модели через постоянную сессию CLI (прогрета коротким запросом при запуске). Ученик сделал 4 хода (23.Qd3, 23...Ra7, 25.Nd3, 25.Ke3).

| Ход | Вердикт движка, мс | Модель, мс | Всего, мс |
|---|---|---|---|
| 23.Qd3 | 6646 | 3370 | 10032 |
| 23...Ra7 | 6214 | 2800 | 9030 |
| 25.Nd3 | 2802 | 1684 | 4499 |
| 25.Ke3 | 2776 | 1983 | 4772 |

- Модель в постоянной сессии отвечает за 1.7-3.4 с.
- Вердикт движка без заранее посчитанного анализа занимает 2.8-6.6 с: `multipv: 3` по позиции, а для хода вне тройки ещё запрос с `searchmoves`. Поэтому в помощнике обязателен заранее запущенный анализ `lesson.node`, пока ученик думает (план, задача 12, шаг 2): тогда вердикт хода из тройки и хода из карточки мгновенный, а ход вне тройки ждёт один запрос `searchmoves`.
- Очередь ученика модель не тронула: ходы пробы пришли тренеру в сообщении ученика через хук `coach inbox --hook`.
- Сбой пробы: модель вложила JSON в поле `say`, и на доске появился сериализованный JSON. `parseReply` (задача 11) должен отвергать `say`, который сам разбирается как JSON.

### Решения по итогам задачи 1 (обязательны для задач 3-14)

Ученик выбрал скорость (постоянная сессия устраивает) и задал требования к странице и репликам. Ниже решения тренера, которые из этого следуют. Где они расходятся с текстом плана, прав этот раздел.

1. **Способ вызова модели: `stream`.** Один процесс `claude -p --input-format stream-json --output-format stream-json --verbose --model haiku --safe-mode --setting-sources "" --strict-mcp-config --tools "" --no-session-persistence --system-prompt <SYSTEM_PROMPT> --json-schema <REPLY_SCHEMA>` на позицию. Без `--effort` (с `low` больше нарушений формата). Ответ - `structured_output` события `result`, запасной путь - `result`.
2. **Окружение запуска модели:** `process.env` без всех переменных с префиксами `CLAUDE` и `ANTHROPIC` (не только `CLAUDECODE`). Рабочая папка `os.tmpdir()/chess-coach-lesson`.
3. **Прогрев позиции.** На каждой новой позиции сессия сбрасывается, и сразу, пока ученик думает над ходом, в неё уходит первое сообщение со статичной частью контекста (привычка, позиция, задание, идея, карточка); ответ на него отбрасывается. Запросы на события ученика несут только изменчивую часть (ходы, вердикт, факты, последние реплики, что сделал ученик, что можно, формат). Так ученик ждёт 2-3 с вместо 6-7.
4. **`LESSON_MODEL_TIMEOUT_MS = 15000`** (запрос на событие может ждать конца прогрева).
5. **`modelExplainsWrong = true`**: ученик просит «текстом объяснение идеи».
6. **В текстах для ученика нет нотации ходов и цифр оценки.** Реплики тренера, фразы карточки, заготовки, `wrongText` и плашка вердикта объясняют идею словами. Фигуры можно называть с полем («конь d3»), ходы нельзя («25...Qxc3+»). Ходы показываются на доске (линия, ход тренера), оценка - шкалой с числом. `parseReply` отвергает любой ход в нотации (SAN фигуры, взятие пешкой, рокировка, ход с номером) и любую оценку (`+1.2`, `#3`, `мат в 3`) в `say`; тогда `knownSan`, `knownEvals` и `forbiddenSan` не нужны. `parseCard` и `lesson check` проверяют то же во фразах карточки. Плашка вердикта: `Верно`, `Неплохо, но есть сильнее`, `Ошибка`, `Не могу проверить ход: движок недоступен`. Для журнала и очереди основного тренера ход и оценка остаются: в `LessonVerdict` появляется `score` (со стороны белых), очередь пишет `25.Nd3 - ошибка (-1.1)`.
7. **Шкала оценки с числом в режиме занятия** появляется вместе с вердиктом после хода ученика и берётся из `lesson.verdict.score`, а не из панели движка. Пока ученик думает (нет вердикта), шкалы нет. Панель движка в занятии выключена, как в плане.
8. **Показ ходов подряд.** Линию тренера (опровержение, вариант из карточки, разыгрывание) и ход тренера клиент проигрывает по одному ходу с паузой (`LESSON_REPLAY_MS = 800`), стрелки появляются в конце. Сервер сообщает, что проигрывать: `lesson.replay = { from, to, id }` (узлы начала и конца, id растёт с каждым показом).
9. **Блокировка доски.** Пока тренер отвечает (`phase: 'coach'`) и пока идёт показ, ходить и листать нельзя, поле ввода выключено, на странице видно, чего ждём. Ход ученика сервер принимает только в фазе `student` с курсора `lesson.node`, всё остальное отклоняется.

### Одобренный дизайн (остановка Б закрыта, 2026-10-18)

Ученик принёс дизайн из Claude Design: проект `c1603ec5-cf90-4acd-b0fc-1c8ad69886c2`, файл `Занятие у доски.dc.html` (там же `pieces.js`, `support.js`, бриф и скриншоты). Читать через `DesignSync` (`get_file`, `projectId` выше). В файле переключаются 8 состояний и 5 размеров окна, внизу «Правила раскладки». Задача 6 делает страницу по нему; ниже то, что из него обязательно, и где он меняет план.

**Раскладка.** Вся страница в окне без прокрутки, прокручивается только история. Сверху строка состояния (36), под ней доска со шкалой и колонка тренера. Считаются две раскладки, берётся та, где доска крупнее:

- стопка (тренер под доской): `min(W - 68, H - 84 - P)`, `P = 320` - минимальная высота панели тренера (84 = поля 24 + строка состояния 36 + зазоры 24);
- колонки (тренер справа): `min(H - 72, W - 420)` (72 = поля 24 + строка 36 + зазор 12; 420 = поля 24 + шкала 44 + зазор 12 + колонка 340), колонка тренера `min(560, W - 80 - доска)`, лишняя ширина уходит в поля;
- формулы взяты из кода `layout()` в файле дизайна; в тексте «Правил раскладки» там написано `H − 96 − P` и `H − 60`, это опечатки дизайна, примеры ниже считаются по коду;
- размер доски округляется вниз до кратного 8, но не меньше 280. При высоте 860 колонки выигрывают с ширины около 880. Примеры: 630×860 - стопка, доска 456; 1280×760 - колонки, доска 688, колонка 512.
- Шкала оценки занимает свою колонку 44 всегда, даже пустую, чтобы доска не прыгала. В стопке группа «шкала + доска» по центру.
- Когда места мало: сначала полоса движка сворачивается в одну строку, потом уменьшается доска (до 280), потом история (до 140). Поле ввода (44) не сжимается.

**Колонка тренера** сверху вниз: полоса движка, история, поле ввода.

- История - чат по текущей позиции: реплики тренера пузырём слева (плашка вердикта, текст, у итога серии - строка цвета `--coach`), фразы ученика пузырём справа, ход ученика меткой справа «ход на доске `25.Nd3`», пока тренер отвечает - последней записью «Тренер отвечает» с точками. Кнопки действий стоят под последней репликой тренера и уезжают вместе с историей. Новые записи прокручивают историю вниз.
- Поле ввода - скруглённое, кнопка «↑», Enter отправляет, до 500 символов. Подсказка: «Ход на доске или короткая фраза»; после «почему?» - «Ответь фразой или покажи ход на доске»; при блокировке - «Подожди, тренер отвечает» или «Подожди, идёт показ ходов»; без помощника - «Помощник не подключён».

**Строка состояния**: «Занятие: <title>» и серым « · позиция k/n»; в конце серии « · серия пройдена, n/n». Пока тренер отвечает - спиннер и «Тренер отвечает…» цветом `--coach`; во время показа - «Показываю ходы… k из n»; без помощника - красным «Помощник у доски не подключён. Напиши тренеру в чат». Справа кнопка «Ходы партии ▾»: всплывающий список ходов партии до позиции занятия (последний ход подсвечен `--current`), подпись «В занятии ходы не листаются: позиция задаётся тренером». Целиком в колонке список виден только без помощника, где история пуста.

**Блокировка.** Пока тренер отвечает: на доске вуаль `--veil` с меткой «Тренер отвечает» и точками, курсор «нельзя», поле и кнопка выключены. Во время показа ходов вуали нет (ходы должны быть видны), но доска, поле и кнопки так же выключены. Ходы и клики в это время отбрасываются, в очередь не ставятся.

**Плашки вердикта**: «Верно» `--free`, «Неплохо, но есть сильнее» `--weaker` с тёмным текстом, «Ошибка» `--frozen`, «Не могу проверить ход: движок недоступен» `--off`. Новые переменные: `--off` (#8a8a8a / тёмная #6f7378), `--veil` (rgba фона 0.5), `--soft` (#f1eee8 / #27292c). Тема только системная, переключатель тем и размеров в файле - инструмент прототипа.

**Кнопки по состоянию** (меняют план): после ошибки - «Попробовать другой ход» (`lessonRetry`) и «Повторить показ»; после показа без ошибки - «Повторить показ» и «К позиции» (`lessonRetry`); позиция решена - «Дальше» (`lessonNext`); конец серии - кнопок и поля нет, только итог и «Возвращайся в чат: напиши тренеру, что закончил». «Повторить показ» - только клиент: заново проигрывает последний `lesson.replay`, к серверу не идёт.

**Полоса движка** (меняет план: раньше панель движка в занятии была выключена целиком). Полоса стоит над историей во всех состояниях, слева переключатель.

- Пока ученик думает над ходом и пока тренер отвечает, полоса закрыта, переключатель выключен: «Движок скрыт, пока ты думаешь над ходом», «Оценка появится вместе с ответом».
- Во время показа в полосе идёт показываемый вариант, текущий ход подсвечен.
- После вердикта - оценка и линии позиции на доске. Развёрнуто три линии, если после разворота истории остаётся не меньше 200, иначе одна строка: оценка и лучшая линия. Заголовок развёрнутой полосы - движок и глубина из ответа сервиса (в макете написано Stockfish 17, у нас 19).
- Переключатель скрывает и линии, и шкалу. Без помощника занятие стоит, переключатель доступен, по умолчанию выключен.
- Шкала оценки появляется вместе с вердиктом и берёт число из `lesson.verdict.score` (решение 7); без помощника, при включённом переключателе - из анализа.

**Решение тренера поверх дизайна** (отменяемо): после вердикта «Ошибка» или «Неплохо, но есть сильнее» полоса показывает оценку и только показанное опровержение, а не три линии, до конца позиции. Причина: ученик сейчас нажмёт «Попробовать другой ход», а в линиях движка есть верный ход (в макете в линии после 25.Ke3 стоит 26.Nd3). Это главное правило занятия: лучший ход не называется, пока ученик его не нашёл.

**Конец серии**: история заменяется одной репликой «Позиция n из n решена» с плашкой «Верно», под ней итог (`summary`) и строка «Возвращайся в чат: напиши тренеру, что закончил». Поля нет.
