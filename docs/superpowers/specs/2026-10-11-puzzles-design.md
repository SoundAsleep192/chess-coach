# Задачи: дизайн (этап 3, подпроект 1)

Дата: 2026-10-11. Статус: согласован в чате, ждёт проверки спецификации учеником.

## Зачем

Ученик каждый день решает тактику по темам своих слабостей из профиля. Задачи берутся из хороших источников, решаются на живой доске из этапа 2а, повторяются по интервалам. Тренер (Claude) видит результаты по темам и подбирает следующие.

Успех:

- В базе есть задачи из трёх источников: Lichess с фильтром качества, Полгар «5334 задачи», Дорофеева «Радуга тактических приёмов» 1-7. Задачи в несколько ходов входят наравне с одноходовыми.
- `coach puzzles next --theme fork` ставит задачу на доску. Ученик решает её мышью, ответы соперника ставятся сами, неверный ход засчитывается как ошибка.
- Повторение по FSRS: задачи, которые ученик решил плохо, возвращаются раньше.
- `coach puzzles stats` показывает процент решённых по темам и источникам.

## Источники

### Lichess

База `lichess_db_puzzle.csv.zst` с `database.lichess.org` (CC0). Перед загрузкой тренер называет ученику точный размер файла. Фильтр качества: `Popularity >= 90`, `NbPlays >= 1000`, рейтинг задачи от 800 до 2400. Темы Lichess берутся как есть.

В CSV первый ход в `Moves` делает соперник. При импорте он применяется к `FEN`, так что в базе позиция всегда с ходом решающего, а `solution` начинается с его хода.

### Полгар, «5334 Problems, Combinations & Games»

PDF собран LaTeX, диаграммы набраны шахматным шрифтом и читаются `pdftotext` как строки по 8 символов (`0Z0SpZ0Z`). `0` - пустое светлое поле, `Z` - пустое тёмное, фигуры на светлых полях - `KQRBNP` и `kqrbnp`, на тёмных - другие буквы того же шрифта (например `S` - белая ладья, `M` - белый конь, `j` - чёрный король). Таблица соответствий выводится по первым страницам и проверяется: в каждой позиции ровно по одному королю, пешки не на крайних горизонталях, позиция легальна в `chess.js`.

Тема и сторона хода берутся из главы и подписи к диаграмме (`Mate in 1`, `Mate in 2`, `Mate in 3`, комбинации с указанием, чей ход). Решения берутся из раздела ответов книги. Если ответ для номера не разобран, решение считает Stockfish (см. «Решения от движка»).

### Дорофеева, «Радуга тактических приёмов», тома 1-7

Сканы 600 dpi, на странице четыре диаграммы с номерами, тема в заголовке страницы («Двойной удар»), сторона хода отмечена треугольником справа снизу от доски (белый или чёрный).

Распознавание диаграмм:

1. `pdfimages` извлекает страницы в PNG.
2. Рамки досок находятся по проекциям тёмных пикселей на строки и столбцы.
3. Доска делится на 64 клетки, каждая клетка классифицируется сравнением с образцами: 12 фигур и пустое поле, на светлом и тёмном фоне. Образцы снимаются один раз с двух-трёх страниц, разметку которых тренер делает по изображению и проверяет глазами. Шрифт диаграмм во всех томах один.
4. Номер задачи и заголовок страницы читаются `tesseract` (установлен на хосте), треугольник стороны хода - по доле тёмных пикселей внутри него.

Ответы в конце седьмого тома (и в конце остальных томов, если они там есть) набраны фигурками и отсканированы. Их переписывает тренер по изображениям страниц в `data/books/raduga-answers.json` в формате `{ "<том>-<номер>": "1.Nf5+ Kg8 2.Nh6+ ..." }`. Каждый ответ проверяется: вариант должен быть легален из распознанной позиции. Несовпадение значит, что ошибся либо распознаватель, либо переписчик: позиция уходит в отчёт импорта, а не в базу.

Тема из заголовка переводится в словарь Lichess: «Двойной удар» - `fork`, «Связка» - `pin`, «Отвлечение» - `deflection`, «Завлечение» - `attraction`, «Уничтожение защиты» - `capturingDefender`, «Открытое нападение» и «Вскрытое нападение» - `discoveredAttack`, «Двойной шах» - `doubleCheck`, «Перекрытие» - `interference`, «Освобождение поля» и «Освобождение линии» - `clearance`, «Мат» и «Матовые атаки» - `mate`. Заголовок без соответствия сохраняется в `themesRaw` и попадает в отчёт, словарь дополняется.

### Решения от движка

Если ответа из книги нет, решение строится по правилам генератора Lichess. Ход решающего входит в решение, если он единственный: Stockfish даёт разницу не меньше 15 пунктов win% (порог зевка из `coach.toml`) между первым и вторым ходом, либо это мат. Ход соперника - лучший по Stockfish. Линия заканчивается матом, перевесом от +3 или после 8 ходов решающего. Позиция, где уже первый ход не единственный, в базу не попадает. Stockfish берётся из `engines/` через небольшую обёртку UCI на TypeScript.

Ответ из книги тоже проверяется движком: первый ход книги должен быть матом или не хуже лучшего хода движка больше чем на 5 пунктов win%. Если хуже, позиция помечается `disputed` и в выдачу не попадает, пока тренер её не посмотрит.

## Данные

Mongo, та же база `board`.

Коллекция `puzzles`:

```
{
  _id: "lichess:00sHx" | "polgar:0123" | "raduga:3-021",
  source: "lichess" | "polgar" | "raduga",
  fen: string,            // ход решающего
  solution: string[],     // UCI: решающий, соперник, решающий, ...
  themes: string[],       // словарь Lichess
  themesRaw?: string[],   // исходные названия из книги
  rating?: number,        // только Lichess
  ref?: string,           // "Полгар №123", "Дорофеева, т.3 №21"
  solutionFrom: "lichess" | "book" | "engine",
  disputed?: boolean
}
```

Коллекция `cards` (FSRS, `ts-fsrs`, MIT): `_id` равен id задачи, поля карточки FSRS, `due`, и `history: [{ at, correct, ms, grade }]`.

Оценка для FSRS выставляется сама: неверный ход - `Again`, верно, но дольше 60 секунд - `Hard`, верно - `Good`. `Easy` не используется.

## Компоненты

- `web/packages/puzzles` (новый пакет, TypeScript): импорт Lichess, разбор Полгар, распознавание «Радуги», обёртка UCI, словарь тем, отчёт импорта. Запускается на хосте: `npm run import -w @board/puzzles -- lichess|polgar|raduga`. Импорт повторяемый: задачи обновляются по `_id`, карточки FSRS не трогаются.
- Сервер (`web/packages/server`): модуль `puzzles` с REST `POST /api/puzzles/next` (тело `{ theme?, source? }`), `GET /api/puzzles/stats`. Доска получает режим `puzzle` рядом с `frozen` и `free`.
- Клиент: в режиме `puzzle` плашка «Задача: <ref или тема>, ход белых/чёрных», после решения «Решено» или «Ошибка, правильно: ...» с показом решения на доске.
- `coach` (Python, только HTTP через `urllib`, как `coach board`): `coach puzzles next [--theme X] [--source S]`, `coach puzzles stats [--since YYYY-MM-DD]`.
- Темы по умолчанию для `next` берутся из `coach.toml`, секция `[puzzles] themes = [...]`. Её заполняет тренер по профилю. Словарь «категория ошибки → темы» записан в `CLAUDE.md`: «пропущенный свой удар» - `fork`, `pin`, `skewer`, `discoveredAttack`, `deflection`, `attraction`, `doubleCheck`, `mate`; «пропущенная угроза соперника» - `defensiveMove`; «зевок материала» - `hangingPiece`, `trappedPiece`; «вариант не досчитан» - `long`, `veryLong`.

## Ход решения

1. `next` выбирает задачу: сначала карточки с наступившим `due` в нужных темах, затем новые задачи этих тем, Lichess по рейтингу ближе к рейтингу ученика из профиля (`coach.toml`, `[puzzles] rating`).
2. Сервер заменяет дерево доски: корень - позиция задачи, режим `puzzle`, ориентация - сторона решающего. Номер версии растёт как обычно.
3. Ученик делает ход. Сервер сверяет его с `solution` по UCI. Последний ход решающего засчитывается и тогда, когда он отличается от решения, но даёт мат.
4. Верный ход: сервер добавляет его в дерево, через 0,5 секунды добавляет ответ соперника. Неверный ход: ход остаётся в дереве веткой ученика, задача считается нерешённой, решение добавляется главной линией, режим становится `free`, чтобы ученик посмотрел решение.
5. По итогу сервер пишет запись в `history` и пересчитывает карточку FSRS.

## Ошибки

- Импорт не останавливается на одной плохой позиции: она попадает в отчёт `data/books/import-<source>.md` с причиной (нелегальная позиция, нет ответа, ответ нелегален, спорный ответ, неизвестная тема).
- Нет Stockfish или `tesseract` - импорт книг завершается с понятной ошибкой до начала работы.
- `next` без подходящих задач отвечает 404 со списком тем, по которым задачи есть.
- Ход в режиме `puzzle` после завершения задачи обрабатывается как в режиме `free`.

## Тесты

- Разбор шрифта Полгар: синтетические строки диаграмм в тестах, не текст книги.
- Распознавание «Радуги»: эталон из 40 диаграмм разных томов, размеченных тренером по изображению и проверенных глазами, хранится в `data/books/` (не в git). Распознаватель должен совпасть на всех 40. Тест пропускается, если книг нет на машине.
- Генератор решений от движка, проверка ответов, импорт Lichess на трёх строках CSV, выбор задачи по `due`, проверка хода в режиме `puzzle` (верный, неверный, альтернативный мат), FSRS-оценка, `coach puzzles` через фейковый сервер, как в `tests/test_board_cli.py`.

## Приёмка

1. Отчёты импорта: число задач по источникам, число отброшенных с причинами. Ориентир: из «Радуги» в базу проходит не меньше 95% диаграмм.
2. 20 случайных задач из книг: позиция на доске совпадает с картинкой в книге.
3. Во встроенном браузере решить пять задач: одноходовую, мат в 2, задачу из «Радуги» в несколько ходов, задачу с неверным ходом, задачу с альтернативным матом.
4. `coach puzzles stats` показывает эти пять попыток, нерешённая задача стоит в выдаче раньше решённых.
