# Roadmap

## Этап 1 — готово: цикл «партия → разбор → профиль»

Stockfish + python-chess, импорт партий с Lichess и chess.com, разбор с критическими моментами, статистика, доска и HTML-отчёт, профиль ученика, скиллы `build-profile` и `review-game`.

## Этап 2 — живая двусторонняя доска

Сейчас доска односторонняя: тренер показывает, ученик смотрит. Цель — чтобы ученик делал ходы на доске, а тренер их читал.

- Веб-приложение на Vite + React + TypeScript. Доска на `react-chessboard` (MIT), логика на `chess.js` (BSD-2). Chessground не берём: он под GPL-3, и с ним сложно сделать закрытый продукт (см. этап 4).
- `coach serve` — локальный сервер с WebSocket. `coach show` отправляет на него позицию и стрелки, а если сервер не запущен, по-старому пишет файл.
- Ход, сделанный учеником на доске, попадает в очередь. Тренер забирает его командой `coach inbox`. Так сценарий «что бы ты сыграл?» проходит прямо на доске.
- Панель рядом с доской: шкала оценки (по запросу, не всегда видна), линии движка, заметки тренера.
- Линии и перемотка как в анализе Lichess: партия и варианты с ответвлениями, ходы вперёд-назад стрелками и кликом по списку ходов. Восстанавливать продолжение по одной нотации ученику тяжело, это главная причина этапа.
- Режим управляет тренер: заморозить доску на одной позиции или дать ученику листать самому. Стрелки, оценку и линии движка тоже включает только тренер, чтобы держать внимание ученика на нужном.
- Это ядро будущей платформы, так что сразу продумать структуру компонентов.

## Этап 3 — тренировочный контент

- **Maia-2** (CSSLab, MIT, PyTorch; на M1 работает через MPS). Перед установкой сверься с README в github.com/CSSLab/maia2.
  - В разборе: какой ход сыграл бы человек твоего рейтинга и с какой вероятностью. Если Stockfish хочет одно, а Maia твоего уровня почти наверняка играет другое, это слепая зона, типичная для уровня, а значит — тема для тренировки.
  - Спарринг: `coach play --maia 1600` на доске из этапа 2.
- **Задачи.** База задач Lichess (CC0, `database.lichess.org`, CSV с темами и рейтингом) в SQLite. Команда `coach puzzles --theme fork --rating 1500`. Темы берутся из слабостей в профиле. Интервальное повторение на FSRS (`py-fsrs`), задачи из своих партий тоже идут в колоду.
- **Дебюты.** Каталог `lichess-org/chess-openings` (CC0) для определения момента выхода из теории. Репертуар хранится в PGN, тренировка линий с интервальным повторением.
- **Эндшпиль.** API таблиц Lichess (`tablebase.lichess.ovh`) или локальные 5-фигурные Syzygy (около 1 ГБ). Отработка типовых позиций против движка.
- **Lc0.** Нужен, когда соберётся ПК с RTX 3070 (CUDA, 8 ГБ хватит для стандартных сетей). На M1 должен работать через Metal — проверить `brew info lc0`. Для обучения даёт немного поверх Stockfish, но на нём же запускаются веса Maia-1.
- **Эксперимент.** Дообучить Maia на своих партиях и получить «цифрового двойника», который предсказывает твои ходы. Позиции, где двойник уверенно ошибается, станут персональным набором задач. Тут пригодится 3070.

## Этап 4 — платформа

- Ядро `coach` превратить в MCP-сервер с инструментами analyze, review, show, puzzles, profile. Тот же сервер будет работать и в Claude Code, и в веб-приложении.
- При этом перенести `coach` с Python на TypeScript отдельным пакетом в монорепозиторий `web/` (решение от 2026-10-10: весь проект на одном языке, ученик не пишет на Python). Замены: `chess.js`, разбор PGN с ветками, своя обёртка над UCI для Stockfish, MCP SDK для TypeScript. Страховка: новая версия на тех же партиях должна совпасть с сохранёнными разборами в `data/reviews/` по классам ходов и критическим моментам, сверка автоматическая. До этого этапа `coach` остаётся на Python и работает на хосте, вне Docker.
- Веб-приложение с Claude через Claude API или Agent SDK, профили нескольких учеников, вход через Lichess OAuth для импорта партий.
- Лицензии:
  - Stockfish (GPL-3) на сервере использовать можно.
  - Если распространять бинарник вместе с приложением, придётся соблюдать GPL.
  - Фронт делать на MIT/BSD-библиотеках.
  - Данные Lichess под CC0, Maia-2 под MIT.
  - API Lichess и chess.com: соблюдать лимиты запросов и их правила.
