# Этап 2а: живая доска с линиями и перемоткой

_Спецификация от 2026-10-10. Согласована с учеником в обсуждении, ждёт его проверки в виде этого файла._

## Зачем

Сейчас доска односторонняя: тренер рисует позицию в `out/board.html`, страница обновляется раз в 2 секунды, ученик только смотрит. Главная боль, ради которой затеян этап 2: продолжение партии или варианта приходится пересказывать нотацией, а ученику трудно держать в голове ходы, которых нет на доске. На сегодняшнем занятии это было видно на 43...Kf5 в otb-FqtJXvRK: маршрут коня на c4 и вариант с Nc2 пришлось показывать отдельными статичными позициями.

Этап 2а решает именно это: тренер загружает партию и варианты, ученик листает их как в анализе Lichess и может делать свои ходы, а тренер видит его ветки.

Критерий успеха: сценарий из раздела «Приёмка» проходится во встроенном браузере Claude Desktop без пересказа ходов словами.

## Что входит и что нет

Входит:

- сервер доски на Node + Nest с хранением в MongoDB, всё в Docker;
- веб-клиент на Vite + React + TypeScript с доской `react-chessboard` и логикой `chess.js`;
- дерево ходов с вариантами, перемотка кликом и с клавиатуры;
- режимы «заморожено тренером» и «свободный просмотр»;
- ветки ученика, видимые тренеру;
- команды тренера `coach board ...` и перевод `coach show` на сервер.

Не входит, отдельные части этапа 2:

- **2б.** Очередь ходов ученика (`coach inbox`) и хук Claude Code, который прикладывает её к сообщению ученика. Выбран хук, а не автопробуждение тренера: ученик сначала пишет, о чём думал, и тренер не отвечает на полуслове.
- **2в.** Панель рядом с доской: шкала оценки, линии движка, заметки тренера.

Не входит совсем:

- HTML-отчёты по разборам (`coach report`) остаются как есть.
- Партии, разборы и профиль остаются файлами в `data/` и `profile/`. Перенос в базу - этап 4.
- Python-утилита `coach` остаётся на Python и работает на хосте, вне Docker: Stockfish там использует все производительные ядра M1 без виртуализации, а тренер вызывает `coach` десятки раз за занятие. Перенос `coach` на TypeScript записан в этап 4 в `ROADMAP.md`.
- Доступ с других устройств. Доска открывается только на этом Mac.

### Монорепозиторий `web/`

npm workspaces, три пакета:

- `web/packages/shared` - типы состояния доски и протокол сообщений WebSocket и HTTP. Его импортируют и сервер, и клиент, поэтому формат сообщений не может разойтись.
- `web/packages/server` - Nest. Раздаёт собранный клиент, держит WebSocket для браузера и HTTP API для тренера, хранит состояние в MongoDB.
- `web/packages/client` - Vite + React + TypeScript, `react-chessboard` (MIT), `chess.js` (BSD-2).

Chessground не используется: GPL-3 мешает закрытому продукту на этапе 4.

### Docker

`docker-compose.yml` в корне репозитория, два сервиса:

- `board` - образ с собранным сервером и клиентом. Порт наружу только `127.0.0.1:8765:8765`, тот же порт, что у нынешней доски.
- `mongo` - официальный образ, именованный том для данных, порт наружу не открыт. Есть healthcheck, `board` стартует только после него (`depends_on: condition: service_healthy`).

Конфиг `board` в `.claude/launch.json` запускает `docker compose up board` вместо `python3 -m http.server`, порт 8765. Встроенный браузер открывается через `preview_start` с именем `board`, как сейчас.

Для разработки Mongo поднимается из compose, а сервер и клиент можно запускать локально с горячей перезагрузкой (`npm run dev` в `web/`, Vite проксирует API и WebSocket на сервер).

Версии Nest, адаптера WebSocket, `react-chessboard`, библиотеки PGN и образа Mongo фиксируются при установке по их актуальной документации, а не по памяти. Node на хосте 20.17, Nest 11 требует 20 и выше.

### Почему сервер хранит состояние

Рассматривались три варианта: состояние на сервере, состояние в браузере (сервер только пересылает сообщения), без сервера на файлах. Выбран первый:

- тренер читает то же дерево одним запросом, не дожидаясь вкладки;
- перезагрузка или закрытие вкладки ничего не теряет;
- окончательная проверка ходов в одном месте.

Без сервера ходы ученика не вернуть, а состояние в браузере теряется вместе с вкладкой.

## Данные

### Документ доски

Коллекция `boards`, один документ на доску. В 2а доска одна, её `_id` фиксирован (`"main"`). Под нескольких учеников на этапе 4 добавится поле владельца.

```ts
interface BoardDoc {
  _id: string;                 // "main"
  version: number;             // растёт на 1 при каждом изменении
  rootFen: string;             // стартовая позиция дерева
  nodes: Record<NodeId, Node>; // плоский словарь узлов
  rootId: NodeId;              // корневой узел (позиция rootFen, без хода)
  cursor: NodeId;              // узел, который сейчас на доске
  mode: "frozen" | "free";
  orientation: "white" | "black";
  meta: { title?: string; gameId?: string; plyOffset: number }; // plyOffset: номер полухода корня, нужен для нумерации ходов и адресации --at N
  updatedAt: Date;
}

interface Node {
  id: NodeId;           // короткий устойчивый id, например "n17"
  parent: NodeId | null;
  children: NodeId[];   // первый ребёнок - продолжение главной линии этого узла
  san: string | null;   // ход, который привёл в этот узел (null у корня)
  uci: string | null;
  fen: string;          // позиция после хода
  ply: number;          // номер полухода в нумерации review
  author: "game" | "coach" | "student";
  arrows: Arrow[];      // стрелки, видимые только в этой позиции
  caption?: string;     // подпись под доской в этой позиции
}

interface Arrow { from: string; to: string; color: "green" | "red" | "blue" }
```

Плоский словарь, а не вложенные объекты: так проще адресовать узел по id, обновлять один узел и не упираться в глубину вложенности документа. Размер с запасом укладывается в лимит документа Mongo 16 МБ: партия с вариантами - это сотни узлов.

FEN хранится в каждом узле. Это избыточно, но позволяет отрисовать любую позицию без проигрывания ходов от корня.

### Дерево как чистые функции

Операции над деревом живут в отдельном модуле сервера без зависимостей от Nest и Mongo:

- `addMove(tree, parentId, uci, author)` - если такой ход уже есть среди детей, вернуть существующий узел, иначе создать новый;
- `addLine(tree, parentId, sanMoves[], author)` - цепочка ходов, возвращает последний узел;
- `deleteBranch(tree, nodeId)` - удалить узел и всё поддерево, курсор переходит на родителя, если был внутри;
- `pathTo(tree, nodeId)` - узлы от корня до данного;
- `mainLineNodeAtPly(tree, ply)` - узел главной линии с данным номером полухода;
- `toPgn(tree)` - PGN с вариантами в скобках и комментарием `{ученик}` у веток ученика;
- `fromGame(pgnOrMoves, upto?)` - построить дерево из партии, при `upto` обрезать главную линию.

Легальность ходов проверяет `chess.js`. Для чтения PGN с вариантами нужна отдельная библиотека разбора, потому что `chess.js` варианты не читает. Выбирается по двум условиям: лицензия MIT, BSD или Apache, и в тесте она правильно читает вложенные варианты.

## Протокол

### WebSocket: браузер и сервер

Сервер → браузер:

- `state` - полное состояние доски (`BoardDoc` без служебных полей). Отправляется при подключении и после каждого изменения. Браузер игнорирует состояние с `version` меньше уже полученного.
- `error` - `{ code, message, version }`, например отклонённый ход. Браузер откатывает фигуру и показывает сообщение.

Браузер → сервер:

- `navigate { nodeId }` - перейти к узлу. Только в режиме `free`.
- `move { parentId, uci }` - сделать ход из узла. Только в режиме `free`. Сервер проверяет легальность, вызывает `addMove` с `author: "student"`, ставит курсор на результат.
- `deleteBranch { nodeId }` - удалить ветку. Только ветки с `author: "student"`.

Переворот доски не отправляется на сервер: он локальный для вкладки.

### HTTP: тренер и сервер

Все запросы идут на `http://127.0.0.1:8765/api/board`. Тело и ответы в JSON, ответ на изменение - новое состояние. Позиция `at` - либо номер полухода главной линии (число), либо id узла (строка `n17`).

| Метод и путь | Тело | Что делает |
|---|---|---|
| `GET /api/board` | - | Текущее состояние |
| `GET /api/board/pgn` | - | Дерево как PGN с ветками и пометками ученика, плюс курсор и режим в заголовках PGN |
| `PUT /api/board` | `{ pgn | fen, moves?, cursorPly?, upto?, orientation?, title?, gameId?, plyOffset? }` | Заменить дерево целиком: партия или одна позиция |
| `POST /api/board/lines` | `{ at, moves, caption? }` | Добавить вариант от позиции `at`, `author: "coach"` |
| `PATCH /api/board/cursor` | `{ at, arrows?, caption? }` | Перевести курсор, поставить стрелки и подпись в этой позиции |
| `PATCH /api/board/mode` | `{ mode }` | Заморозить или открыть доску |
| `DELETE /api/board/nodes/:id` | - | Удалить ветку (тренер может удалять любые) |
| `GET /api/health` | - | Сервер жив и база доступна |

Изменения применяются по очереди внутри одного экземпляра сервера. После каждого изменения документ целиком сохраняется в Mongo, `version` растёт на 1, состояние рассылается всем вкладкам.

## Экран

Слева доска, справа список ходов. При узкой вкладке список уходит под доску.

- **Доска.** Подсветка последнего хода. Стрелки и подпись текущего узла. Кнопка «перевернуть» только для этой вкладки.
- **Плашка режима над доской.** «Заморожено тренером» или «Свободный просмотр». В замороженном режиме перетаскивание фигур, клики по списку и клавиши отключены.
- **Список ходов как в анализе Lichess.** Главная линия парами «1. e4 e5». Варианты в скобках с отступом под ходом, от которого они отходят. Текущий ход выделен. Клик по ходу - переход. Ветки ученика одним цветом, ветки тренера другим, ходы партии обычным текстом. У веток ученика есть кнопка удаления.
- **Навигация.** Кнопки «в начало», «назад», «вперёд», «в конец». Клавиши: влево и вправо - ход назад и вперёд по текущей линии, Home и End - начало и конец линии, вверх и вниз - выбор варианта в точке ветвления.
- **Ход ученика.** Перетаскивание фигуры в режиме `free`. Если ход совпадает с существующим ребёнком, это просто переход. Превращение пешки через диалог `react-chessboard`.
- **Связь.** При обрыве WebSocket плашка «нет связи» и автоматическое переподключение с нарастающей паузой. После переподключения приходит полное состояние.

Тема светлая и тёмная по системной настройке, как у нынешней доски.

## Команды тренера

Python-утилита `coach` получает тонкий HTTP-клиент на стандартной библиотеке (`urllib`), без новых зависимостей. Номера полуходов везде в нумерации `review`: `--ply N` означает позицию перед полуходом N.

| Команда | Запрос | Что делает |
|---|---|---|
| `coach show [позиция] [--game ID --ply N] [--moves ...] [--best ...] [--played ...] [--arrows ...] [--caption ...]` | `PUT /api/board` | Как сейчас: одна позиция, стрелки и подпись. При запущенном сервере заменяет дерево этой позицией. Без сервера пишет `out/board.html`, как раньше, и печатает, что работает без сервера |
| `coach board load --game ID [--ply N] [--upto N] [--white\|--black]` | `PUT /api/board` | Партия главной линией, курсор перед полуходом N. `--upto` обрезает партию, чтобы ученик не подсмотрел продолжение. Ориентация по умолчанию - цвет ученика |
| `coach board line --at N --moves "..." [--caption ...]` | `POST /api/board/lines` | Вариант тренера или движка от позиции N. Ходы проверяются на сервере, при ошибке печатается, какой ход нелегален |
| `coach board goto N [--arrows ...] [--best ...] [--played ...] [--caption ...]` | `PATCH /api/board/cursor` | Курсор на позицию N со стрелками и подписью |
| `coach board mode freeze\|free` | `PATCH /api/board/mode` | Заморозить или открыть доску |
| `coach board state` | `GET /api/board/pgn` | PGN дерева с ветками ученика, курсор, режим, список id узлов вариантов |
| `coach board delete <id>` | `DELETE /api/board/nodes/:id` | Удалить ветку |

`CLAUDE.md` (раздел «Доска» и таблица инструментов) обновляется под новые команды в рамках реализации.

## Ошибки

- **Сервер не запущен.** `coach show` откатывается к файлу. `coach board ...` завершается с кодом 1 и подсказкой запустить `docker compose up board` или `preview_start` с именем `board`.
- **Нелегальный ход.** Браузер заранее проверяет через `chess.js`, сервер проверяет окончательно. Отклонённый ход: `error` по WebSocket, фигура возвращается. Для HTTP: ответ 422 с указанием хода.
- **Ход, перемотка или удаление в режиме `frozen`.** Сервер отклоняет с кодом `frozen`, браузер показывает это на плашке режима.
- **Узел не найден.** Ответ 404, `coach` печатает ошибку и текущее дерево через `state`.
- **Ученик удаляет чужую ветку.** Сервер отклоняет с кодом `forbidden`.
- **Mongo недоступна при старте.** `board` не стартует до healthcheck. Если база отвалилась во время работы, изменение не применяется, клиенту и `coach` уходит ошибка `storage`, `/api/health` отвечает 503.

## Тесты

- **Дерево (модульные).** `addMove` с существующим и новым ходом, `addLine` с нелегальным ходом посередине, `deleteBranch` с курсором внутри ветки, `pathTo`, `mainLineNodeAtPly` с ненулевым `plyOffset`, `toPgn` с вложенными вариантами и пометками ученика, `fromGame` с `upto`. Отдельный тест на выбранную библиотеку PGN: партия с вложенными вариантами читается без потерь.
- **Сервер (интеграционные).** Nest с Mongo в памяти (`mongodb-memory-server`): загрузить партию через HTTP, получить `state` по WebSocket, сделать ход из браузера, получить ветку ученика в `GET /api/board/pgn`, заморозить и убедиться, что ход отклонён, переподключиться и получить то же состояние, перезапустить сервер и убедиться, что состояние сохранилось.
- **Клиент.** Vitest и Testing Library: отрисовка списка ходов с вариантами и пометками, навигация стрелками и выбор варианта вверх и вниз, блокировка в режиме `frozen`.
- **Python.** Тесты на `coach board` против поддельного HTTP-сервера и на откат `coach show` к файлу без сервера.
- **Приёмка.** Сценарий ниже вручную во встроенном браузере.

## Приёмка

На позиции из сегодняшнего занятия, otb-FqtJXvRK перед 43...Kf5:

1. `docker compose up` и `preview_start` с именем `board` открывают доску во встроенном браузере.
2. `coach board load --game otb-FqtJXvRK --ply 86 --upto 86` ставит партию до 43-го хода чёрных, чёрные снизу, курсор на позиции перед 43...Kf5. Пролистать дальше этой позиции нельзя.
3. `coach board mode free`. Ученик листает партию назад к 39-му ходу и обратно.
4. Ученик ходит Kd6 на доске. Появляется его ветка. `coach board state` показывает её с пометкой ученика.
5. `coach board line --at 86 --moves "Kd6 Ne2 Ne5 Nd4 Nc4+ Ke2"` добавляет вариант тренера. Ход Kd6 совпадает с веткой ученика, поэтому вариант продолжает её, а не дублирует.
6. `coach board goto` на позицию с конём на c4 со стрелками на a3 и e3. Ученик видит её и листает вариант сам.
7. `coach board mode freeze`. Перетаскивание и клики больше не работают, плашка показывает режим.
8. Перезапуск `board` не теряет дерево.
9. При остановленном сервере `coach show` пишет `out/board.html`, как раньше.
